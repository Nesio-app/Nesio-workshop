# 实体解析设计 · 把半图补成真图(2026-07)

> 一页施工图。锚定 `path:符号`,可 grep 复验。承接批次198/199(记忆图 + 学习态已进账号级云银行)。
> 前置:198/199 需真机 + 真 Supabase 实测跨端后再下刀(见 `nesio-sync-verify-todo`)。

## 0. 一句话

实体解析不是「没有」,是**只做了一半、只覆盖人、且全靠手动**。缺的三块——自动认亲、扩到物/地、跨类型连边——才是把「半图」变成「别人重建不出来的结构化生活图」的那一刀。而每一次用户确认的合并,正好是「被纠偏的 ②级 harness」——该进批次199 的银行。

## 1. 先纠偏:解析已经有了(某报告「无实体解析」的说法过时)

`lib/portal/entity-resolution.ts`(批次194)已提供:

- `normalizeEntityKey`:NFKC + 大小写/引号/空白归一(同写法收敛)。
- 用户可维护**别名表** + `resolveEntityKey` / `mergeEntity` / `unmergeEntity`(「妈妈/母亲/妈」→ 一个规范键)。
- **但只接进了 `lib/portal/relationships.ts:195`(人)**,读时派生用。

## 2. 真缺口(三条,按含金量)

1. **纯手动**:没有任何「自动认亲建议」。用户得自己点 `mergeEntity`。全仓无 `suggestMerge/autoMerge/共现`——零候选检测。
2. **只覆盖人**:object / place **不走** `resolveEntityKey`。同一地点不同叫法、同一物品散落的提及,不收敛。
3. **没有跨类型边**:解析只在「人」内部收敛,不建 person↔object↔place 的边——而这正是「此人↔此物、此地↔此需」,也是 `mineCrossDomain` 和未来巡查真正想站的底座。

## 3. 设计:确定性优先的三层(仿 relationships/cross-domain 的读时派生、本机、可回退)

**L0(已有,保留)**:normalize + 手动别名。地基,不动。

**L1 — 自动认亲候选(确定性信号,不猜)**:新建 `entity-candidates.ts`,读时扫本地图,产出「疑似同一实体」建议卡,**只建议、绝不自动合**(用户一键确认才落 `mergeEntity`):
- 强信号(高置信):同一 email / 同一 phone / 规范键相等但当前散落。
- 中信号:名字编辑距离近(「张伟」vs「张玮」)、高频共现。
- 走 guidance-pipeline 出「要不要把 A 和 B 当同一个人?」确认卡——复用现成卡机制,不新造 UI。

**L2 — 扩到 object / place**:`resolveEntityKey` 入口统一给 object/place 用。place 已有 `lib/portal/named-places.ts` 的命名/归一,把它和别名表并成**一个**解析入口(别两套);object 认亲用规范键 + 属性(location/purchaseDate)辅助。

**L3 — 跨类型边(真图那一步)**:派生 person×place(常和谁在哪)、object×place(东西放哪)、person×object(谁的/给谁的)边,喂给 `mineCrossDomain` 和巡查。**读时派生、不回写节点**(仿 relationships 的「不落库」),先只在内存建图供消费。

## 4. 与「银行」的接口(接批次199)

别名表 `nesio-entity-aliases-v1` 现在**只在本机**——换机就丢。用户手动合并「妈妈=母亲」是典型的**「被纠偏」私有资产**,该像 ranker 一样进 P2 学习态银行(加进 `cloud-learning-sync` 的 blob),一并 union 跨端。这是批次199 的自然续集。

## 5. 护城河 vs 会被吃(对齐两级 harness)

- **会被吃**:认亲算法本身(编辑距离、共现、邮箱匹配)——通用,基座迟早会自带。别在算法花俏上恋战,确定性够用就行。
- **抄不走**:①「这个用户三年的**已解析**图」——同一个人跨 200 条记录被收敛成一个节点;② 他**纠偏过的每一次合并**。这两样是 ②级累积,进了银行就带不走也抄不走。**L1 产出 → 用户确认 → 回灌银行**,就是把这份资产越攒越厚的泵。

## 6. 落地顺序(便宜→贵)

1. **L1 强信号候选**(最便宜、最高信噪):同 email/phone/规范键散落 → 确认卡。零算法风险,立刻减少「同一人裂成三个」。
2. **别名进银行**(接批次199):合并决定跨端 + 落袋。小,且战略正确。
3. **L2 统一 place/object 入口**:中等,收口两套归一。
4. **L3 跨类型边 + 喂 mineCrossDomain**:最贵、最像「悟」,压轴。

**先做 L1 强信号 + 别名进银行**(便宜、确定性、直接增厚 ②级),L3 跨类型边留到最后压轴。
